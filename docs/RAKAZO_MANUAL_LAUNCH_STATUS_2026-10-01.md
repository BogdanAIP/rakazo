# Rakazo + ChatGPT R: состояние работ и передача контекста

**Дата фиксации:** 2026-10-01 (вечер).  
**Репозиторий:** `BogdanAIP/rakazo`; рабочая ветка `feature/chatgpt-mcp-upstream-2026-09-29`.  
**Статус:** код единого ручного запуска подготовлен в GitHub; **физическое переключение текущих терминалов на него ещё не проведено**. Документ описывает текущую точку продолжения. Новые коммиты могут появляться параллельно, поэтому перед изменениями читать актуальный HEAD, а не полагаться на устаревшие фрагменты из переписки.

## 1. Окончательное требование пользователя

Один Rakazo как обычное Windows-приложение: пользователь **сам нажимает один ярлык**, контроллер запускает нативные API, Worker, Web, ранее сопряжённый физический Windows Host и **тот же существующий** Plugin R / OpenAI tunnel; показывает одну иконку и меню в трее; повторный щелчок не запускает копии, а Quit завершает только принадлежащие этому запуску процессы. Терминальные окна в штатном использовании не нужны: сервисы запускаются скрыто, журналы остаются локальными.

**Не включать автозапуск Rakazo** при включении ПК или входе в Windows: не создавать Scheduled Task, Registry Run, запись Startup или системную службу. Не создавать второй туннель, alias, Tunnel ID, сопряжение Windows Host, второй API или вторую базу. Не использовать CAP или OpenResearch как обязательный локальный исполнительный слой.

Docker допускается **только для уже существующего PostgreSQL**, пока он не перенесён отдельно: запускать/повторно использовать Docker Desktop и проверенный PostgreSQL-контейнер при необходимости; не запускать прежний Docker-стек приложения, не удалять volumes и не останавливать общий Docker Engine при выходе из Rakazo.

- База для новой версии — копия `rakazo_next` в существующем PostgreSQL; исходная `rakazo` сохраняется для отката.
- API и Web успешно отвечали локально; Worker и Windows Host запускались в отдельных foreground-терминалах. Первые read-only `Preflight` подтвердили нужные исходники, пути MCP, базу, флаги/настройки диспетчера Windows Host, наличие защищённых локальных учётных данных и Corepack.

Локальный защищённый API-запрос к этому Host подтвердил идентичность установки и вернул список пяти процессов. Это подтверждает физическую read-only доставку через API, **но не** доказывает, что старый `ChatGPT Compute` уже переключён с прежнего Docker computer на физический Host.

## 3. Что находится в текущем коде GitHub

Каталог `scripts/windows/manual-rakazo/`:

| Файл | Назначение и текущий статус |
| --- | --- |
| `Rakazo.ps1` | Основной контроллер: read-only Preflight, mutex от второго запуска, проверки старого Tray и внешних процессов/портов, проверка базы, нативный запуск API/Worker/Web/Host, управление существующим R, окно/значок трея и Quit. **Написано, полного физического Start → Quit → Start ещё нет.** |
| `Tunnel.Diagnostics.ps1` | Авторизованная read-only диагностика существующего runtime через прежний защищённый локальный контекст; различает remote ready/healthy, live health endpoint и доказанную идентичность локального процесса. |
| `Tunnel.Control.ps1` | Операции над **существующим** alias с сериализацией на прежнем mutex и проверкой идентичности. Connect допускается только при доказанной полной остановке прежнего R; Stop — только для точного процесса, запущенного и подтверждённого текущим контроллером. Не выполняет admin CRUD/создание нового туннеля. |
| `Check-ExistingR.ps1` | Уже испытанный на ноутбуке read-only тест прежнего R; выводит только безопасные булевы признаки. |
| `Validate.ps1` | Парсер PowerShell и простые запреты опасных операций. Последний новый вариант проверяет также `Tunnel.Control.ps1` и установщик ярлыка; **именно этот вариант ещё нужно выполнить на ноутбуке после обновления ветки**. |
| `Check Rakazo.cmd` | Вход в Preflight. |
| `Start Rakazo.cmd` | Ручной вход в Run; **пока не запускать поверх работающих терминалов и прежнего R**. |
| `Install-Shortcut.ps1` | Отдельная установка обычного ярлыка рабочего стола после успешного физического handoff; никакой Windows Startup. |
| `README.md` | Инструкция, условия пилота, ограничения и сценарий отката. |

Из двух предоставленных пользователем старых локальных исходников `Rakazo.Common.ps1` / `Rakazo.Action.ps1` изучен только контур управления **туннелем**. Старые `app-start/app-stop` запускают Docker-приложение и **не должны** попадать в новую архитектуру. Полные исходники/конфигурации/локальные ключи не переносить в публичный GitHub.

В нынешнем `Rakazo.ps1` уже есть `Ensure-ExistingPostgres`: он может поднять Docker Desktop при необходимости, перепроверяет идентичность конкретного существующего PostgreSQL-контейнера, запускает только его и ждёт health. `Quit` не останавливает PostgreSQL или общий Docker Engine. Это реализация в коде, а не доказательство её физического прохождения на данном ПК.

## 4. Критически важное различие состояний R

CLI выводит JSON с `ready`, `healthy`, `process_running`, `runtime_state`, `tunnel_id`, а не единое текстовое поле `status`. Старые ложные `ExistingTunnelReady=False` возникали из-за неверного чтения вывода. Авторизованная проверка затем подтвердила remote-ready + live health при отсутствии доказанного PID.

**Remote ready не равен доказанному праву на остановку локального процесса.** Новый Run при обнаружении живого R, старого Tray, внешнего Host/Worker или занятых API/Web обязан завершаться безопасно, не запускать дубликаты и не убивать процессы по общему имени. Планируемый cold start возможен лишь после преднамеренной остановки старого alias и подтверждения `ExistingTunnelColdStartAllowed=True`.

Сохранять прежние alias/Tunnel ID и защищённые локальные файлы. Не выводить сырое CLI JSON, локальные ключи, session data, полные команды/пути в публичный файл.

## 6. Как откатиться при проблеме

Не удалять исходный checkout, старый V4 launcher, обе базы или защищённые локальные credentials. Если новый Run не прошёл, не запускать второй alias и не очищать Docker. Сначала безопасно завершить только явно принадлежащие новому контроллеру процессы; вернуть ранее определённые foreground-компоненты из той же рабочей копии, проверить API/Worker/Host и заново использовать **исходный tunnel-only Start** того же R. Если идентичность или состояние процесса не ясны, остановиться и уточнить, а не выполнять принудительное завершение.
