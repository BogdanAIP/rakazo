# Algorithm Discovery v13 — ручной запуск, конечная сессия, продолжение с контрольной точки

**Рабочая версия от 30 октября 2026.** Это исследовательский управляющий модуль поверх уже созданного и зафиксированного плана v12, **не отдельный торговый бот**.

## Как запустить без команд

На Windows в отдельной исследовательской рабочей копии Rakazo откройте двойным нажатием:

`C:\Users\eahra\rakazo-alpha-manual-v13-20261030\scripts\trading\START_ALGORITHM_DISCOVERY_MANUAL_v13.cmd`

Однократный запуск обрабатывает до **пяти** заранее назначенных на ТЕКУЩУЮ дату UTC инструментов, по одному короткому восьмисекундному публичному WS-сеансу для каждого. Если сегодняшний день не входит в календарь или все пять уже зарегистрированы — программа **ничего не скачивает** и завершается. Пока она работает, компьютер должен быть включен и иметь интернет. После завершения можно выключить ноутбук. Постоянного наблюдения, автозапуска, фонового процесса и самостоятельных действий завтра **нет**.

Альтернатива: попросить ChatGPT «Запусти следующую ручную сессию Algorithm Discovery». Подключённый Rakazo R может вызывать один ограниченный шаг через отдельную короткую команду, при необходимости последовательно продолжать на другие назначенные рынки в рамках одного явного пользовательского запроса. Нельзя считать это гарантией, что ChatGPT продолжит работу за пределами текущего диалога.

## Что уже умеет

1. Считывает **без изменения** ранее замороженный 12-дневный план `multiday-v12-20261030/plan.json` и проверяет SHA-256 календаря, 50-инструментного состава и 5 заранее назначенных контрактов на дату.
2. Не собирает данные **до 1 ноября 2026**, не подменяет инструменты и не пытается восполнить пропущенные дни задним числом.
3. На ручном запуске под блокировкой ОС открывает только публичные WebSocket `books` и `trades-all` OKX через существующий строго ограниченный 8-секундный коллектор. Ни аккаунт, ни торговые API не используются.
4. Сохраняет исходные сообщения в уникальный путь `ws-v12-YYYY-MM-DD-COIN`, проверяет хеш, последовательность `prevSeqId → seqId`, хронологию и полноту, добавляет ровно одну запись в журнал v12. Если подлинная исходная папка уже существует после прерванной регистрации, пытается продолжить проверку **именно её**, не скачивает повторно.
5. Ошибку API или невалидное исходное сообщение регистрирует как **неполное/отклонённое наблюдение**, а не делает повторные попытки, подбирая удачные события.
6. После каждой законченной ручной сессии пишет отдельную цепочку `manual-runner-v13/sessions/000001.json`, `000002.json` и т.д. с SHA текущей записи и предыдущей; состояние восстанавливается из исходного журнала и этих файлов. Одновременные запуски запрещаются блокировкой операционной системы, которая освобождается даже после завершения процесса.
7. Создаёт небольшой **детерминированный генератор 12 символических гипотез-кандидатов** из двух семейств taker-потока, трёх семейств изменений видимой глубины и двух способов их композиции. Каталог проверяется по контрольной сумме. Все 12 кандидатов имеют явный статус `UNTESTED_HYPOTHESIS_PROPOSAL`; это **не генерация научно новых алгоритмов LLM и не самообучение**, без будущих цен они не получают ни прогноза, ни доходности.

**Не умеет пока:** самостоятельно проводить исследования LLM с открытым поиском новых гипотез; получать подтверждённые будущие цены после сигнала (в v11 такой запрос был заблокирован); честно оценивать торговую доходность; открывать сделки или PAPER; решать задачу непрерывного сбора данных, когда ноутбук выключен. Эти возможности не следует имитировать.

## Календарь и ограничения

Сохраняется неизменным исходный план: 1–6 ноября разработка, 7–9 ноября валидация, 10–12 ноября закрытая контрольная выборка. Всего 60 заранее назначенных слотов, по 5 за UTC-день. **Кандидатная модель должна быть отдельно формально зафиксирована до 7 ноября 00:00 UTC**, иначе данные валидации и holdout нельзя выдавать за независимое подтверждение.

Первый день: **1 ноября 2026 (UTC)** — ETH, BTC, ZEC, SOL, PEPE (`-USDT-SWAP`). Пропущенные дни или источники записываются как пропуски, а не заполняются выдуманными сделками или снимками.

Каждый кандидат из символического каталога до подлинной проверки на новых источниках и самостоятельной экономической модели имеет `can_trade=false`, `can_start_paper=false`. Система **не выбирает победителя** по уже просмотренным исходам v6–v11 и не оптимизирует параметры на контрольных днях.

Откройте командную строку в отдельной папке исследования:
`C:\Users\eahra\rakazo-alpha-manual-v13-20261030`.

Замените `<ROOT>` на:
`C:\Users\eahra\RakazoRuntime\trading-live-data-20261011\alpha-research\pit-captures`.

Статус без подключения к бирже:

```bat
python scripts\trading\algorithm_manual_runner_v13.py --study "<ROOT>\multiday-v12-20261030" status
```

Одна короткая ручная сессия (один контракт максимум, удобно при вызове через R):

```bat
python scripts\trading\algorithm_manual_runner_v13.py --study "<ROOT>\multiday-v12-20261030" run --max-captures 1
```

Для двойного щелчка по `.cmd` установлено `--max-captures 5`, то есть до пяти конечных процедур в одной foreground-сессии. Максимум жёстко ограничен пятью, никакого повторения «до появления прибыли» нет.

## Происхождение данных и ограничения гарантий

Все исходные папки и цепочки SHA находятся на локальном Windows-хосте. SHA-256 выявляет обычную подмену файлов, но не является цифровой подписью биржи; если атакующий контролирует все исходные файлы и меняет все хеши, локальный журнал не защитит от такого сценария. Поток `trades-all` не гарантирует математически полную последовательность всех сделок, хотя у `books` контролируется очередность дельт. Обычный стакан может не включать всю RPI-ликвидность.

Никакие будущие метки доходности не создаются, пока нет отдельно авторизованного надёжного источника и предварительно зафиксированной методики оценивания. **Запуск v13 проверяет организацию исследовательского процесса, но не доказательство альфы.**

**Граница безопасности:** никакого изменения `main`, активного Trader/PAPER, реальных счетов, приватных API, платных источников, расписаний и фоновых служб.
