# Algorithm Discovery v16 — как проверить пятиминутный прогноз после выключения ноутбука

**Создано 30 октября 2026. Все действия ручные и ограниченные; никакие реальные/PAPER-сделки не выполняются.**

## Найден практический новый тип источника

Официальная страница OKX **Historical Market Data** сообщает о доступных для скачивания исторических данных стакана L2, сделок и свечей: https://www.okx.com/en-us/historical-data . Указано L2 с марта 2023 года. Официальные обновления документации OKX также описывают функцию получения пакетов исторических данных (включая книги 400 и 5000 уровней): https://www.okx.com/docs-v5/log_en/ .

Это означает, что **в принципе** 5-минутное движение можно проверять по опубликованному позже архиву того же дня: ноутбук не обязан работать все пять минут после каждого зарегистрированного прогноза. Это не равно непрерывному сбору. Важные ограничения: насколько быстро архив появляется после окончания дня, все ли 50 символов доступны и в каком точном формате содержимое L2, на реальном 2026 архиве пока не проверено. Архивы могут быть большими, а возможность скачивания может зависеть от сайта/региона. **Не обещать мгновенную проверку и не выдавать подготовленный импортёр за проверку с настоящими данными OKX.**

## Что реализовано в отдельной ветке v16

- `scripts/trading/algorithm_historical_l2_v16.py`: строго офлайновый разбор одного предоставленного вручную `.tar.gz` c одним JSONL/NDJSON файлом `snapshot/update`, реконструкция полного видимого стакана (qty=0 удаляет ценовой уровень), проверка при наличии `seqId/prevSeqId`, строгого возрастания времени, котировки не старше пяти секунд до целевого `capture_end+300000ms` и наличие события не позже пяти секунд после целевого времени, подтверждающего покрытие. Никогда не использует событие **после** целевого времени для определения цены на выходе. Если архив указывает `instId` или `symbol`, проверяет его совпадение с ранее зафиксированным контрактом; если не указывает — отчёт об этом честно сообщает.
- `scripts/trading/algorithm_archive_origin_v16.py`: локально создаёт одноразовый файл происхождения `origin.json` с хешем исходного `.tar.gz`, введённой пользователем URL-страницей/ссылкой и временем записи. **Обязательное поле `exchange_origin_independently_verified=false`** — никаких ложных утверждений о цифровой подписи биржи.
- Исследовательская модель v14/v15 должна быть зарегистрирована **до начала новой записи**; прогнозный `source-signals` JSON должен быть зафиксирован в конце той же 8-секундной записи и **не позже 15 секунд после неё**, то есть до наступления пятиминутного результата. Первичная WS-запись повторно проверяется по SHA-256 и последовательности книг. Без исходного зафиксированного прогноза архив сам по себе **не является проверкой**.
- На выходе сохраняется единственный неизменяемый JSON с `entry bid/ask` из исходного WS, `exit bid/ask` из более позднего пользовательского архива, гипотетической валовой доходностью в bps с пересечением спреда и условными комиссиями 5bps на сторону / стресс 7bps на сторону. **`realized_pnl=null`, `counts_toward_validated_alpha=false`**. Нет размеров контрактов, подтверждений реального исполнения, funding/mark, проскальзывания и цены комиссии конкретного счёта.
- Архив и записанный прогноз используют разные часовые домены: локальное время приёма WS и биржевое `ts` архива. Отклонение часов/латентность не подтверждены, поэтому точные 300 секунд являются **приближённой привязкой к часовым меткам**, а не доказательством целевой сделки в точности через 5 минут.
- Чистота научной проверки: v12 имеет 60 разных market-day-слотов; два алгоритма на одной записи не создают дополнительных независимых наблюдений. v16 производит только ПРОБНЫЕ расчёты в development-части календаря (1–6 ноября UTC) и не открывает validation/holdout до отдельного model freeze.

## Порядок ручной работы через этот чат

**Шаг 1 — сначала сделать прогноз.** Не раньше 1 ноября 2026 UTC пользователь пишет «Запусти Algorithm Discovery». Через подключённый R запускается одна ограниченная исследовательская сессия из `C:\Users\eahra\rakazo-alpha-historical-v16-20261030`:

```bat
python scripts\trading\algorithm_chatgpt_cycle_v14.py --study C:\Users\eahra\RakazoRuntime\trading-live-data-20261011\alpha-research\pit-captures\multiday-v12-20261030 --max-captures 1
```

За несколько секунд будет сохранена SHA-верифицированная исходная восьмисекундная запись одного назначенного инструмента, а затем отдельное условное направление (либо ABSTAIN) для **каждой из двух** ранее зарегистрированных гипотез. После выхода из программы ноутбук можно выключить. Никакие последующие данные не нужны для формирования прогноза.

**Шаг 2 — дождаться публикации архивных данных ОТДЕЛЬНО.** Когда OKX разместит архив L2 для соответствующего UTC-дня и инструмента, пользователь вручную открывает https://www.okx.com/en-us/historical-data , выбирает **Order book**, нужный инструмент, нужный день и скачивает архив. Не скачивать специально неизвестный платный инструмент, не регистрировать платный аккаунт без согласия пользователя. Исходный файл оставить без изменений. Если формат отличается от `tar.gz` с JSONL внутри — **остановиться, зафиксировать формат и адаптировать парсер после проверки реального файла**, а не притворяться, что он поддерживается.

**Шаг 3 — пользователь пишет в чат:** «Архив OKX за [дата] для [монета] скачан, проверь». Rakazo сможет прочитать файл из предоставленного пути, зафиксировать его SHA и проверить совместимость.

Для опытной ручной диагностики (если файл находится по пути `<ARCHIVE>`):

```bat
python scripts\trading\algorithm_archive_origin_v16.py --archive "<ARCHIVE>" --symbol ETH-USDT-SWAP --source-url "https://www.okx.com/en-us/historical-data" --out "<ARCHIVE_FOLDER>\origin.json"
```

Затем только для уже **подходящего** заранее зарегистрированного source-signal в development-дне, например `flow-memory-flip-20261030`:

```bat
python scripts\trading\algorithm_historical_l2_v16.py --study "C:\Users\eahra\RakazoRuntime\trading-live-data-20261011\alpha-research\pit-captures\multiday-v12-20261030" --candidate "flow-memory-flip-20261030" --date 2026-11-01 --symbol ETH-USDT-SWAP --archive "<ARCHIVE>" --origin-metadata "<ARCHIVE_FOLDER>\origin.json" --out "<ARCHIVE_FOLDER>\provisional-signal-outcome.json"
```

Для второго алгоритма имя `impact-efficiency-decay-20261030`, но он должен независимо от первого иметь допустимый исходный условный сигнал. **Не пытаться рассчитать доходность на ABSTAIN или по незарегистрированному прогнозу.**

Если пользователь не умеет пользоваться командной строкой, можно вручную обращаться к Rakazo прямо в ChatGPT; он будет выполнять эти ограниченные шаги. Запущенная сессия всегда завершается.

## Научные различия

1. Биржевой архив с ценами после прогноза потенциально позволяет оценить *последующую фактическую котировку*, даже если в момент её публикации ноутбук был выключен.
2. Даже правильное архивное bid/ask **не гарантирует**, что была бы исполнена покупка и продажа по этим ценам, в нужном объёме, без дополнительного проскальзывания. Поэтому считать настоящую доходность PAPER/реального трейдера нельзя.
3. Исторический OHLCV файл не является архивом bid/ask. Подставлять цены закрытия свечей вместо котировки исполняемой стороны стакана для рыночного входа/выхода нельзя.
4. SHA-256 и HTTPS URL, введённая пользователем, не являются независимой аттестацией происхождения архива. Пока не проверен действительно официальный архив, счёт остаётся **предварительным** (`USER_SUPPLIED_UNAUTHENTICATED_OFFLINE_ARCHIVE`). Чтобы перейти к доверенным статистическим выводам, нужна отдельная доказуемая цепочка получения и верификации источника и более длинная независимая программа наблюдений.

## Проверки и статус

Синтетические регрессионные тесты проверяют корректность восстановления лучших bid/ask, удаление уровня и последовательность дельт, недопустимость цен из будущего, stale/перепутанные инструменты, неподходящую исходную регистрацию, математические комиссии и обязательную маркировку недоказанного происхождения. **Это подготовленный офлайн импортёр, а не уже обработанный реальный официальный архив**. До ноябрьских источников новых рыночных исходов не существует.

No automation, no account changes, no remote order API, no alternate network endpoint bypass, no background data collection.
