## Source reconstruction

Use original v30 archive receipts, full source spool SHA-256 and indexed snapshot
line SHA-256. Replay every original delta in UTC 01:00..09:16 and 13:00..15:01,
anchored to the nearest earlier original snapshot. At every minute T take the
book strictly BEFORE T (target T-1ms), no future update in the feature. Past and
next source-event age brackets must satisfy the existing 5-second tolerance.
Sequence IDs are absent in the originals, so continuity cannot be certified.

Between minute boundaries count positive and negative displayed quantity changes
at the previously best bid and ask prices. Do not count complete snapshots as
additions. A minute containing a snapshot reset cannot supply a restoration
feature; abstain and reset memory. This loses some decisions and must be reported
against the expected 1,868. Apply the same availability filter to all baselines.

For each side restoration share = positive changes / (positive + negative
changes), or neutral 0.5 if no quantity changes. Restoration imbalance is bid
share minus ask share. Combine it with actual strictly prior executed taker flow,
its temporal change and original top-five displayed imbalance. Positive quantity
changes are observable posting activity, not proof of order identity, icebergs,
execution versus cancellation, or a causal market mechanism.
