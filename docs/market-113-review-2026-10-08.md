# Rakazo Market: аудит 113 записей и проверка цепочек

**Снимок:** 8 октября 2026 года. **Область:** платформа Rakazo, не реализация отдельных продуктов ComicChat, AIHOT или Trading.

## Краткий итог

В живом Market найдено **113 записей**: 91 `skill` и 22 `resolver`. Полный машиночитаемый список находится в [market-113-inventory.csv](market-113-inventory.csv). Это **каталог знаний/провайдеров**, а не перечень 113 установленных исполняемых инструментов. Наличие записи в Market не означает, что навык установлен, инструмент подключён, назначен проекту, авторизован или выбран для вызова.

В глобальном `agentSkills/list` Rakazo находятся **16 Agent Skills**. Из каталога Market подтверждены четыре установленных представления: `chrome-devtools`, `review-duplication`, `build-mcp-server` (оригинальные инструкции) и `CCXT PAPER Market` (WRAPPED-адаптация `ccxt-mcp`). Эти установки не создают сами по себе MCP-исполнителей. В проверенной доступной capability-поверхности есть Microsoft Learn и универсальный каталог подключённых инструментов; отдельные CCXT и Chrome DevTools MCP маршруты при поиске **не обнаружены**. Нативный Rakazo `computer/browser` вызывается через appContract R, независимо от Market.

## Классификация всех 91 Skills

| Группа | Число | Практическое решение |
| --- | ---: | --- |
| `GENERAL_REFERENCE` | 37 | Переиспользовать инструкции по разработке, документации, браузеру и проверкам. Вызовы только через реально доступные инструменты; не устанавливать все подряд. |
| `RESEARCH_REFERENCE` | 17 | Чтение/анализ только при подтверждённом источнике данных, схеме и лицензии. Отсутствие API означает `UNAVAILABLE`. |
| `ADAPT_REQUIRED` | 17 | Адаптация допустима лишь для конкретного подтверждённого случая. Не импортировать по умолчанию полномочия исходных биржевых/кошелёчных клиентов. |
| `PAPER_REFERENCE` | 9 | Исходники для изолированных тестов/симуляций. Сам Market не разрешает проведение PAPER-операций. |
| `LIVE_REFERENCE_ONLY` | 11 | Только справочный материал, не назначать автоматически инструменты финансовых операций. |
| **Итого** | **91** | Все строки и источники перечислены в CSV. |
Группы взаимно исключаются по приоритету тегов; один Skill может содержать теги нескольких групп. Это **рекомендательная классификация аудита**, а не автоматическая выдача прав. Например, GitHub-подобный Skill пригоден как инструкция без установки дополнительного инструмента, но для чтения репозитория всё равно необходима авторизованная GitHub-связь либо проверенный локальный worktree.

## Дубликаты и происхождение

По точному совпадению SHA-256 исходного содержимого, а не только по названию, обнаружены **две пары**:
- `query-token-audit`: записи `ccxt/ccxt` и `binance/binance-skills-hub` содержат идентичный текст.
- `crypto-market-rank`: эти же два источника также содержат идентичный текст.

Файлы и записи Market не удалялись: разные `repository` и `sourceRef` важны для происхождения. Для гипотетической будущей **одной** установки можно предпочесть запись CCXT с явной лицензией MIT, но перед использованием необходимо повторно подтвердить разрешения и фактический инструмент. Дубликат одного текста не следует устанавливать дважды.

## Все 22 Resolvers: назначение и готовность

В каталоге есть: `browser.semantic`, `browser.debug`, `browser.visual`, `computer.exec`, `computer.files`, `repo.read`, `repo.write`, `media.capture`, `research.web`, `market.data`, `market.analysis`, `market.data.provider`, `signal.discovery`, `trading.paper`, `paper.simulation`, `backtest.quant`, `strategy.framework`, `futures.data`, `market.risk`, `wallet.analytics`, `defi.data`, `defi.protocol.metrics`.

Resolver описывает альтернативные реализации, порядок и ограничения, **но не осуществляет автоматический исполняемый вызов**. Проверенные здесь семантические направления: `browser.semantic` через встроенный Browser v2; `computer.exec` через текущий Host и lease; `repo.read` через связанный локальный Git worktree. `browser.visual` имеет доступный экран Host, но отдельный end-to-end тест медиа в этом аудите не выполнялся. Для остальных Resolver необходим выбор реального инструментального маршрута по актуальным разрешениям; их функциональную готовность аудитор не приписывает одному только индексу.
Исходный `market/resolver-seeds.v1.json` ранее ставил внешний Playwright MCP первым, хотя проверенная реальная цепочка **Rakazo Browser v2**: `auto -> playwright-cli-persistent -> opencli`. В данной ветке источник исправлен: `rakazo:computer/browser` первый, внешний MCP — дополнительная явно авторизуемая альтернатива. CDP и Extension остаются только по отдельному разрешению пользователя. Это изменение **версии исходного seed для следующих импортов**: оно само не переписывает старую индексированную запись Market, привязанную к прежнему `sourceRef`, и не перезапускает Host.

Маршруты выбраны через существующие декларативные Skill и Resolver с проверкой доступности, затем **фактически вызваны** указанными инструментами. Это пока подтверждённый управляемый workflow, а не доказательство наличия полностью автоматического универсального Resolver-исполнителя в платформе.

## ORIGINAL / WRAPPED / RCCL / HYBRID
- **ORIGINAL:** источник всегда сохраняется с URL, хэшем и лицензией. Работает как документация без имплицитной установки CLI/MCP.
- **WRAPPED:** существующий `ccxt-mcp` ограничен чтением публичных рыночных данных и изолирован от исполнения сделок; обёртка уже установлена как `CCXT PAPER Market`, но доступного CCXT-вызова здесь нет.
- **RCCL:** `technical-analysis` прошёл строгий профиль `rccl-skill-v1`; инструкция сокращена с 9307 до 3639 символов (~61%), но без проверенного калькулятора и OHLCV ничего не вычислялось. Это экономия контекста, не измеренный прирост скорости.
- **HYBRID:** `chrome-devtools-cli` использует действующий `R-Browser` для обычной семантической автоматизации. DevTools-функции сети, памяти, производительности не объявляются эквивалентными Browser v2 и требуют отдельного авторизованного CLI/MCP.

В существующем **R-Tool-Selector** закреплён повторно используемый playbook: поиск установленного Skill → выбор версии в Market → чтение Resolver → проверка tool-schema, назначения и авторизации → минимально привилегированный вызов → проверка результата → очистка временной сессии → запись evidence. Новый браузерный или торговый исполнитель **не создавался**.

## Статус и остающиеся границы

**Завершено в рамках аудита:** инвентаризация 113, классификация каждой записи, точные дубликаты, анализ состояния установки, три фактические read-only / browser цепочки и одна явно заблокированная, исправленный browser Resolver seed + тесты.

**Не подтверждено:** 113 реально работающих инструментов, автоматический runtime-selection для каждого Resolver, доступность внешних клиентов из оригинальных SKILL.md, одинаковое поведение разных адаптаций в исполнении, все возможные доменные workflows. Эти утверждения потребуют отдельного подключения/авторизации и измерений, а не новых низкоуровневых функций.

**Безопасность:** отдельный Trading-проект не изменялся, реальные или PAPER-ордера не исполнялись, API-ключи не запрашивались, новый Windows Host не запускался, авторизованный Chrome/Tuta не использовался. Данные Market и sourceRef сохраняются; публикация патча seed в GitHub сама по себе не переписывает живую БД.
